# Agent Workspace feature roadmap

> **Progress:** Phase 0 (command policy and migration registry, but not the macOS packaging gate), 1a (session naming, safe paste, local screenshot paste), 1b (keep-awake) and 2a (local English dictation) are implemented and verified on Linux. A live session board (board cards are the running sessions; owner-requested, outside the numbered phases) is also implemented and verified on Linux; it consumed schema v4 as `board_lanes`, so each reserved migration below moves to the next unused number. See `docs/release-evidence.md`. Section 1 below is the original plan. The owner later chose English only and "type as I talk" with no preview step, and the engine became sherpa-onnx instead of whisper.cpp. The release evidence explains both changes.

Baseline: `jerrizzy001/agent-workspace`, `claude/jolly-clarke-oo3rm5`, commit `7b7ec9627c7df7ad71a78db2a09dc8cde8e85a88`, version 0.3.0. Research date: 2026-10-30. This document specifies future implementation; it does not claim that the proposed features have shipped or passed verification.

## Starting point and release gates

The existing application already opens Claude, Codex and shells directly in registered folders through `terminal.open`, with optional model, initial prompt and worktree. It already has a desktop folder browser, login-shell PATH discovery, task attempts, canvas notes/layouts, optimistic file saves, Git review, Claude per-session status hooks, ended-session screen capture and Claude resume. These are foundations to extend, not missing features to rebuild.

`src/core/index.ts` is the sole SQLite owner and owns private tmux sessions, launch receipts/intents, terminal viewers, generation checks and reconciliation. `src/desktop/main.ts` starts it in a utility process; `preload.ts` exposes named methods to a sandboxed renderer. `gateway.ts` provides paired-owner browser control of a fixed shared-project set, with explicit command fields, viewer aliases, bounded queues and revocation. Its cookie represents the owner, not a team member. A terminal still runs with its executing OS user's privileges: project-scoped app APIs are not an OS sandbox for shell commands.

Schema 2 stores JSON records alongside receipts, events, launch intents and immutable launch requests. Existing IDs, receipt digests, backend names/sockets, generations, task relationships and running processes must survive every phase. Closing a view detaches it; only an explicit process action terminates it. A timeout or transport loss leaves an uncertain outcome: inspect the durable receipt and existing backend, never automatically relaunch, resend input or manufacture a replacement session.

Before shipping the first feature, reproduce the relevant baseline checks on the integration commit and a real macOS package. `docs/release-evidence.md` records Linux development/container and unpacked Linux results, not macOS 0.3.0 packaging. Dock PATH discovery is unverified on macOS; the real Claude check reached only an unauthenticated first-run screen; full Claude hook/model turns and Codex runtime/resume were not verified. WebKit, standalone/Linux release checks, physical phones and external routes also remain unverified for 0.3.0. The CLI help research below improves flag evidence, not those runtime claims. Preserve these distinctions in subsequent release evidence.

Effort labels describe scope, not calendar promises: **S** = one bounded subsystem with a few existing integration points; **M** = several process/data/UI boundaries plus recovery and platform checks; **L** = architectural or multi-platform/service work requiring separate milestones. Prerequisites and verification can dominate any label.

## Shared implementation rules

### Authority and transport

Add a typed command-policy registry in proposed `src/shared/command-policy.ts`, used by desktop dispatch, remote validation and future controller dispatch. Keep payload schemas and resource authorization at the receiving core; a UI flag is never authorization. New desktop channels must call the existing main-frame owner check, reject unknown actions/fields and bound payloads. Extend `WorkspaceAPI` with narrow named groups, never a generic native API or subprocess function. Preserve `contextIsolation`, `sandbox`, disabled Node integration, navigation restrictions and CSP. Electron's [security guidance](https://www.electronjs.org/docs/latest/tutorial/security) supports these boundaries.

In this plan **D** means desktop owner only, **R** means an authenticated owner browser within currently shared projects, and **A** means a separately scoped agent-controller capability. D does not become R merely because the operation eventually invokes core code. On an SSH project, ordinary project operations are validated and executed by the remote core; desktop microphone, clipboard, SSH credentials, power and updater remain on the local desktop.

| Proposed surface | Class and routing | Authorization purpose |
| --- | --- | --- |
| Existing `terminal.open`, `attempt.start`, `session.*`, `files.*`, `git.*`, `worktree.*`, `note.*`, `layout.save` | Existing D/R policy retained; execute on project host | Keep current project/viewer/generation checks; A gets only explicitly listed wrappers below |
| Existing `project.add`, `project.hide`, `workspace:browse`, native pickers, `workspace:remote` | D | Host registration, browsing, pairing, TLS and revocation remain owner management |
| `workspace:dictation` actions `status`, `configure`, `start`, `chunk`, `finish`, `cancel` | D; local desktop service | No audio, model download or microphone control route through gateway |
| `workspace:clipboardImage` actions `preview`, `save`, `discard` | D; local clipboard broker and executing-host attachment service | Read one image after a user gesture; no general clipboard/filesystem endpoint |
| `attachment.create`, `attachment.release` | D trusted broker to core; SSH stdio broker when applicable; initially deny R/A | Bounded image bytes, generated destination and session identity, never caller-selected paths |
| `session.rename` | D/R on project host | Plain text label with revision check; no provider invocation; A denied initially |
| `session.place`, `lane.rename`, `lane.add`, `lane.remove` (implemented) | D/R on project host | Session-board lane and placement metadata with revision checks; never restarts, detaches or types into a process; A denied |
| `workspace:power` actions `status`, `setPolicy`, `setTemporaryOverride`, `clearOverride` | D local main process | No browser or agent acquisition of power inhibitors |
| `workspace:profiles` actions `list`, `create`, `setup`, `check`, `remove` | D; selected executing host | CLI-owned authentication and private profile management never cross public gateway |
| `terminal.open` optional `profileId`; `conversation.fork` | D initially; receiving host validates profile/session binding | Gateway rejects profile fields/fork until a later explicit sharing policy; existing default-profile launch remains |
| `transcript.preview`, `transcript.link`, `transcript.revoke` | D on source/target hosts; same-host first | Grants require owner review, not possession of a browser cookie or guessed ID |
| `transcript.read` | D/A with directed grant and recipient identity; initially deny R | Return only approved export, not arbitrary provider history or host paths |
| `workspace:assist` actions `status`, `configure`, `suggestCommit`, `suggestName`, `cancel` | D; selected executing-host helper | Explicit usage/data consent; no automatic provider calls from gateway or controller |
| `workspace:ssh` actions `list`, `add`, `probe`, `connect`, `browse`, `registerProject`, `disconnect`, `remove` | D local management | No raw SSH options, forwarding, host-wide browsing or host installation through R/A |
| `workspace:agent-control` actions `grant`, `revoke`, `list` | D to executing core | Cannot mint capability through owner-browser or agent token |
| Controller RPC `status`, `open`, `note.create`, `note.update`, `canvas.place`, `transcript.read` | A only, separate local socket protocol; approved verbs per grant | No generic `invoke`, terminal input/termination, Git, credentials, project addition or native capabilities |
| `workspace:updates` actions `status`, `check`, `download`, `install`, `setPolicy` | D local updater | No supplied feed URL/package path and no remote forced install |
| `workspace:team` actions `status`, `connect`, `disconnect`, `publishProject`, `revokeProject` | D local account/publication management | Explicit metadata export only; team tokens never grant owner gateway access |
| Team-service `member.list/invite/setRole/remove`, `comment.list/create/edit/delete`, `assignment.set/clear`, `changes.read` | Separate authenticated team API; no core/gateway passthrough | Team/project membership, per-action role and revisions checked by team service |

R is owner-level terminal control, including potentially dangerous shell actions, only for deliberately shared projects. A is a much narrower automation identity, not an alias for the renderer or owner cookie. Team collaboration is a third authority domain. Tests must check all three separately. New fields in snapshots, launch responses and errors require explicit gateway projection: exclude credential references, host installation paths, capability material, private profile paths and unshared transcript relationships. Do not expand the gateway's default-off behavior, exact HTTPS origins for non-loopback listeners, pairing, expiry or revocation rules.

### Additive migrations and compatibility

Extract current initialization into proposed `src/core/migrations.ts` without altering v1→v2 semantics. Add a migration registry with unique names, checksums, ordered prerequisites and a transaction per migration; reject a newer unsupported database before changing it. Take a consistent SQLite backup under the sole-owner lock, with retention and a restore procedure. Do not copy only the main database file while WAL is active. SQLite's [application-owned schema version](https://www.sqlite.org/pragma.html#pragma_user_version) is separate from app SemVer and transport protocol versions.

Reserve this default sequence. If concurrent implementation has already consumed a number, reconcile against its actual schema and assign the next unused number to the same named migration before coding; never overwrite a number or infer compatibility from JSON fields alone.

| Reservation | Additions; existing records stay intact |
| --- | --- |
| `roadmap_01_owner_utilities`, candidate v2→v3 | Private `ownerSettings` record kind with versioned keys for dictation, power, assist and update policy; optional session `title`/`titleRevision`; `attachments` records containing owner session/generation, host, MIME, bytes/hash, relative storage reference and lifecycle timestamps |
| `roadmap_02_conversations`, candidate v3→v4 | `providerProfiles`, `conversationRefs`, `transcriptExports`, `transcriptLinks`; optional session `profileId`, fork-parent reference; source/recipient host+session+generation binding; no credentials in JSON |
| `roadmap_03_execution_hosts`, candidate v4→v5 | `executionHosts` and `remoteProjectRefs`; existing projects/sessions interpret absent host as local; remote cache explicitly nonauthoritative; composite transport references, not rewritten old IDs |
| `roadmap_04_controller`, candidate v5→v6 | Note/layout revisions initialized to 1, controller audit records and namespaced mutation receipts; capability secrets remain ephemeral, outside DB |
| `roadmap_05_team_metadata`, candidate v6→v7 | Local team/project/task mappings, bounded metadata cache, sync cursor and outbox; separate service migration registry for teams, members, comments, assignments and audit events |

Migration fixtures include v1, exact v2, partially failed upgrade, unknown future schema, concurrent owner rejection and real running tmux sessions. Assert unchanged original rows/receipts and live PID/generation, restart with the new build, and prove older builds refuse upgraded stores. Restore for rollback requires stopping the sole core and restoring the complete compatible backup; never downgrade in place or restart tmux to make migration convenient. Introduce new session environment/features only on new launches; existing sessions keep their launch environment. Feature settings may remain absent/default-disabled without rewriting old records. Remote host migration requires its own backup, owner approval to upgrade that host and protocol negotiation; connecting never silently migrates a foreign installation.

## 1. Local voice dictation

**Journey.** The owner chooses a local model once, enables dictation and presses a terminal microphone control or configurable push-to-talk shortcut. A clear recording indicator, elapsed time and Cancel appear. Stop produces an editable transcript preview. Insert pastes text into the originally focused terminal; Enter remains a separate deliberate action. Release microphone tracks on stop, cancel, window loss or failure. Initial scope is the local Electron desktop, including a local UI controlling an SSH terminal; audio is processed on the desktop, and only reviewed text is sent to the terminal host.

**Implementation.** Add `src/desktop/dictation.ts`, a bounded local worker `src/desktop/dictation-worker.ts`, `src/renderer/DictationControl.tsx`, renderer PCM capture/resampling helper and `src/shared/terminal-paste.ts`. Extend `main.ts`, `preload.ts`, contracts, `TerminalView.tsx` and the Session/Canvas terminal wrappers. Use a local whisper.cpp process or audited native wrapper through the service, not renderer Node integration. Prefer a PCM/WAV path without FFmpeg. Start with a pinned CPU model/backend, then qualify Metal/other acceleration separately. Model acquisition is an explicit download/import with source, size, license, revision/hash and disk-space validation; no automatic installation or cloud fallback.

`workspace:dictation` is D-only. Bounded recording chunks belong to one owner-issued recording ID; limit duration, PCM size, workers and inference time. Fix the destination `{executionHostId, sessionId, generation, viewerId, terminalFocusEpoch}` at recording start, then recheck focus, attached viewer, connectivity and generation at insertion. If anything changed, retain the preview for a deliberate destination choice; never insert into whatever terminal is now active, even if focus moved away and back. Sanitize generated text by rejecting terminal controls/escape sequences and flattening CR/LF to spaces for this feature. Use xterm's existing mode-aware `terminal.paste()` path with no appended carriage return, newline or synthetic key. Do not retry uncertain terminal input.

Microphone permission needs both Chromium/Electron permission handling and platform permission. In `main.ts`, use narrowly scoped permission-check/request handlers for the app's trusted main frame, recording gesture and audio-only request; deny other origins, camera and unsolicited capture. Add the macOS microphone usage description and applicable hardened-runtime entitlement during packaging. Do not enable browser microphone access: the current gateway explicitly sets `microphone=()`. A remote browser microphone originates on that browser's machine; uploading its audio to the host while calling it “on your machine” would be misleading. Browser-local WASM transcription is a separate future design and must work without audio upload.

**Data/privacy.** M01 stores preferences/model identity only. Raw audio and uninserted text are memory-only by default; private temporary audio, if required by the binary, is mode 0600 with startup cleanup and a bounded retention deadline. No analytics audio/transcripts, background listening, terminal-output ingestion or OS cloud speech API. After insertion, the receiving CLI may transmit the text to its provider when the user submits it; make that data boundary visible beside Insert.

**Dependencies/platforms.** whisper.cpp and official Whisper code/model weights are MIT; retain notices and verify the exact converted artifact rather than assume every community model shares that provenance. Avoid a wrapper initially; adding one requires its own license/native-build review. macOS needs microphone consent and signed-binary validation, Linux needs working PipeWire/PulseAudio capture and CPU qualification, Windows follows the desktop/WSL plan while transcription stays on Windows. No claim of equal acceleration or latency across machines.

**Verification/size.** **M**, after a shared safe-paste primitive. `tests/dictation.test.ts` uses deterministic PCM and a fixture transcriber; verify permission denial, cancel, huge audio, timeout, model checksum failure, no network, no saved audio, focus/generation changes and exact terminal bytes with zero submit characters. Add `scripts/verify-dictation.mjs` for UI controls/accessibility and a separate opt-in real local-model smoke using a short nonpersonal clip. That local smoke uses no provider credits; benchmark model quality separately. Owner choice: recommended small multilingual model and push-to-talk/preview; model/language and acceptable download/hardware limits block broad voice release, not other phases.

## 2. SSH projects with a local UI

**Journey.** The owner adds an existing OpenSSH host alias, sees host identity and connection diagnostics, confirms trust through the SSH trust workflow, and registers a remote folder. The sidebar visibly distinguishes the host. Claude/Codex/shell, Files and Git operate there. Disconnect detaches the connection and leaves remote tmux processes running; reconnect inspects those same sessions. A missing host/helper/provider displays the executing host's requirement, not a local install suggestion.

**Implementation.** Add `src/desktop/ssh.ts`, `src/core/host-router.ts`, `src/server/stdio-host.ts`, `src/shared/host-protocol.ts`, `src/renderer/SSHProjectsPanel.tsx` and an explicit remote-helper packaging target in `scripts/build-server-release.mjs`. Refactor core construction behind an execution-host interface while retaining `createCore` as the remote and local implementation. The local utility routes opaque `{hostId, remoteProjectId, remoteSessionId}` references; the remote core remains authoritative for sessions, generations, receipts, canonical paths, file hashes, Git/worktrees and terminal streaming. Qualify event/viewer IDs at the transport boundary without rekeying old records or interpreting remote POSIX paths with local Windows path functions.

Use system OpenSSH as an unmodified client, with `ssh -T` for framed, versioned stdio messages to a fixed installed helper entrypoint. Do not transport binary PTY data through newline JSON without bounded base64/framing; retain terminal sequencing/ACK/resync and output backpressure. Negotiation reports host ID, protocol range, schema support, platform and available providers before enabling commands. Remote core ownership locks prevent two helper instances sharing its data; either reuse an explicitly managed existing service or use a dedicated data directory. Do not open a second core against an existing standalone server's data. No public TCP listener or pairing gateway is needed for SSH transport.

Local `workspace:ssh` management is D. The stdio host has its own explicit owner-management bootstrap and ordinary project-command allowlist, not the entire desktop IPC surface. Remote `terminal.open` launches remote binaries with remote profile/environment and durable receipts. Files, Git, transcripts and attachments use remote scoping; an unreachable remote host never falls back to local paths or processes. Probe system `ssh -V`/help and remote Node/Git/tmux/provider versions there. The system client's remote command is shell-interpreted: use a fixed entrypoint with separately validated/quoted installation paths and framed stdin parameters, never interpolate a folder, branch or prompt into SSH command text. Foreground stdio is required; Unix ControlMaster may be an optional later optimization, never a Windows prerequisite.

**Data/security.** M03 stores alias/label, pinned remote host ID, protocol and project mappings; keys/passphrases remain with the user's OpenSSH configuration/agent. Allow aliases and narrow validated port/user overrides, not arbitrary `-o`, `ProxyCommand`, destination strings beginning with `-`, shell snippets or renderer-selected executable paths. Existing owner SSH config can contain proxy commands and is trusted local configuration, never imported from projects. Default `ForwardAgent=no`, no X11/port forwarding, bounded connection/keepalive timeouts, strict host-key checking. Unknown/changed keys require owner resolution with an out-of-band fingerprint; never use `StrictHostKeyChecking=no`, accept changed keys or write user's trust files automatically. A dedicated app known-hosts file is acceptable only with reviewed enrollment.

A malicious remote host must not invoke local clipboard/power/update/credential methods through protocol messages, supply local resource paths, or inject terminal escape-driven local operations. Deny unsupported event kinds and bound all frames/errors. No credential copying to remote hosts; users authenticate the installed provider there. Transfer attachments only after explicit destination preview. Keep SSH projects unshared to browser by default; a later owner share adds only the selected remote project, with the same receiving-host project validation and no SSH-management relay. Loss after launch or write means unknown until remote receipt/file hash/backend reconciliation; never create a fresh launch key to “recover.”

**Dependencies/platforms.** System OpenSSH, Node, tmux and Git; no `ssh2` dependency for first scope. OpenSSH has component-specific BSD/ISC-style licenses; tmux is ISC. Git is GPLv2: use the existing user-installed executable, do not quietly bundle it into a proprietary release. macOS/Linux are first executing hosts. Windows desktop may use Windows OpenSSH to a Linux/macOS host; WSL2 host support needs a separate validated transport/path adapter. Native Windows remote execution is deferred because tmux semantics are absent.

**Verification/size.** **L**, split into read-only host probe, shell continuity, then Files/Git/providers. New `tests/host-router.test.ts`, `tests/ssh.test.ts`, `scripts/verify-ssh.mjs`; use a local disposable SSH server/key and fixture CLIs, no model usage. Test host-key mismatch, malicious frames/paths, protocol mismatch, concurrent core lock, reconnect before/after accepted launch, lost save ACK, stream overflow, no duplicate prompt, unchanged remote PID/generation, no writes to similarly named local files and denial of every desktop-only method. Live SSH smoke is opt-in with one owner-provided disposable host; provider turn is a separate one-prompt budget. Owner must supply host access, approved helper installation location, Node 24+/Git/tmux and authentication there. Recommended first scope: manually installed versioned helper, one host alias, no auto-provisioning; these choices block SSH release only.

## 3. Multiple Claude accounts, conversation branches and transcript links

**Journey.** Launch options select a named Claude profile; each terminal displays its profile label. Add profile opens the installed CLI's own authentication/setup flow in a dedicated terminal. Existing sessions retain their account. Branch creates a separate conversation/session beside an idle or ended original; Resume continues the existing conversation only after it has ended. “Link context” previews a bounded source transcript export and grants a selected recipient agent read access. Links start empty and are directed, visible and revocable.

**Implementation.** Add `src/core/provider-profiles.ts`, `src/core/conversations.ts`, `src/core/transcripts.ts`, `src/renderer/ProfilesPanel.tsx` and `TranscriptLinksPanel.tsx`; extend providers, core, contracts, LaunchBar, SessionView and session labels. `workspace:profiles` manages D-only host-local profile metadata and setup; launch/fork changes are D-only initially. Build a sanitized per-launch environment and set `CLAUDE_CONFIG_DIR` to an owner-managed private profile directory. Do not change `HOME`, global config/auth, shared tmux environment, unrelated sessions or the user's default profile. The inherited/default profile remains backward compatible. Setup runs an unmodified CLI; no embedded app login, token parser, browser-code interception or app-owned Anthropic OAuth flow.

Current official [authentication guidance](https://code.claude.com/docs/en/authentication#log-in-with-multiple-accounts) documents config-directory isolation for supported accounts but excludes two Console OAuth logins without API keys. Hide unsupported combinations; do not claim config-directory isolation universally. Profile deletion is refused while referenced by running/unknown sessions and requires a separate deliberate cleanup of its data; never run global logout. Do not scrape tokens or infer account identity from a directory name. Validate independent sign-in, refresh, sign-out and simultaneous requests in the intended account modes before promising separation.

`conversation.fork` uses the installed CLI's supported `--resume <exact-id> --fork-session`, not prompt replay or screen-tail copying. Verify composition with model/settings flags and child-ID reporting against installed help plus fixtures. Obtain the child conversation ID through a narrowly validated per-session `SessionStart` hook/adapter; do not assume `--session-id` composes with fork. Create a new app session/receipt, generation 1 and explicit parent reference, retaining profile and cwd. Leave the parent process intact; initially require idle/ended coherent provider history and disable unsupported fork points. If child identity or launch outcome is ambiguous, show unknown and reconcile, never resume the parent under a guessed ID. Codex fork exists in current help but is a separate adapter milestone, not a retroactive claim that baseline Codex resume works.

**Transcripts.** Existing `transcripts` are capped tmux screen tails (2,000 captured lines, at most 256 KiB, latest 100), not complete provider conversations; deliberate End does not create one. Keep that record type and UI meaning. A new versioned Claude adapter consumes documented hook `session_id`/`transcript_path` only after validating the source profile, session and real path inside the approved provider storage root. Never accept arbitrary renderer file paths or scan all account history. Parse incrementally with limits, tolerate an incomplete trailing JSONL record, and fail closed on schema drift. Stop does not prove that the last message has flushed. Mark exports complete/partial with watermark, byte count, hash and adapter version. Provider-local storage is a separately verified compatibility boundary.

M02 stores profile labels and credential-location references, conversation lineage, immutable approved export versions and grants scoped to source/recipient host, session, generation, provider and profile. `transcript.preview/link/revoke` are D; `transcript.read` requires a recipient A capability plus its directed grant, with bounded paging and audit. Initially same-host only, no gateway route. Redaction preview can remove selected text but is not a secrecy guarantee. The broker does not call a provider, yet the receiving agent may send read context to its own account/provider; cross-account linking needs explicit disclosure and selection. Revoke blocks future reads; it cannot erase previous context, exports already read, provider history or OS-user filesystem access. Treat all transcript text as untrusted data, strip terminal controls and never execute embedded instructions. No graph-wide transitive sharing.

**Dependencies/platforms.** No auth SDK or new dependency; installed Claude is proprietary/subject to its own terms, not an assumed MIT dependency. Follow its [product-use and authentication terms](https://code.claude.com/docs/en/legal-and-compliance); use each end user's binary/auth/billing, no pooled tokens or account cycling. CLI license/terms review is distinct from open-source library review. macOS Keychain behavior, Linux permission/secret-store differences and Windows/WSL profile roots require account-mode testing; do not assume a directory isolates every credential backend. App-managed secrets, if later necessary, use main-process OS-backed storage only; reject insecure fallback rather than call it encryption ([Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)).

**Verification/size.** **L** overall; profiles **M**, branching **M**, transcript adapter/grants **M**. `tests/profiles.test.ts` checks exact per-session env and unchanged global files with two fixture CLIs; `tests/conversations.test.ts` checks literal exact IDs, lineage, concurrent source, partial fork failure, immutable retries and no parent termination; `tests/transcripts.test.ts` checks schema drift, partial logs, traversal/symlink escape, revoked/stale/cross-profile recipients, secret-bearing preview and bounded output. Opt-in real verification: owner supplies two appropriate profiles; inspect independent auth/refresh/logout without collecting credentials, then one tiny turn per account, one branch and one explicit fixture-only link. Owner decisions: supported account modes, cross-account export policy and retention. Default: same-profile branch, cross-profile sharing only per export; block affected subfeature until proven.

## 4. Agent control of the canvas through a local CLI

**Journey.** The owner grants one running session selected verbs for its project, with expiry and a visible open-session limit. Its agent can run `awctl status`, `awctl open --provider claude --path src --request-id <id>`, `awctl note create --title ... --body-file ...`, or `awctl canvas place --node ... --x ... --y ...`. Results are bounded JSON with durable IDs, revisions and explicit unknown outcomes. The desktop shows actions and Revoke. No account setup or unattended permission escalation is implied.

**Implementation/security.** Add `src/cli/workspace.ts`, `src/core/agent-control.ts`, `src/shared/controller-contracts.ts` and desktop grant UI. A Node `net` Unix socket resides in an app-owned 0700 directory with a 0600 endpoint. Core owns it and the database; the CLI never opens SQLite. D-only `workspace:agent-control` mints a random per-session capability, bound server-side to source session/generation, executing host, project, verbs, expiry, fanout and rate budget. Deliver through a per-process private file/FD or narrowly scoped session environment, never argv, global tmux env, snapshots or logs. Core restart revokes all grants; no automatic regrant. Existing sessions receive a capability only through an explicit grant path, without tmux restart.

Each request authenticates and rechecks current generation, source lifecycle, grant and project. Client-supplied project/session identity cannot widen it. `status` excludes unrelated projects, secrets and transcripts. `open` delegates to `terminal.open` with supported provider/options and a namespaced idempotency key; children do not inherit grant credentials or unlimited ability to spawn grandchildren. Default prompts are blank; allowing a supplied initial prompt must be an explicit grant option and count toward quota. `note.create` and `canvas.place` need independent mutation receipts/digests; `note.update`/placement use M04 revisions to reject concurrent owner edits instead of overwriting them. Place only nodes belonging to that project; retain existing attempt-keyed layout identities and folder-session IDs. Extend CanvasView/snapshot merge to honor revisions while preserving focused-note autosave, unload protection and drag undo.

No generic core RPC, arbitrary executable/options, terminal input/termination, file/Git writes, profile management, gateway/power/update control or grant minting. An agent-created note is inert text, never raw HTML or an executable attachment. Prevent note floods, huge coordinates/content, recursive launches, idempotency-key collision and capability replay after revoke. Same-OS-user processes can often read one another's files/environment: this is API least privilege, not an isolation boundary against a hostile process with the owner's full OS rights.

**Dependencies/platforms/data.** Node built-ins only; no MCP server or new listener dependency. M04 adds revisions/audit/receipts, not persistent tokens. macOS/Linux Unix sockets first. Windows named pipes require owner ACL and token tests; WSL agents connect to their WSL core socket, never a broad TCP bridge. SSH agents use a controller on the remote host with remote grants; they cannot control the local desktop through SSH framing.

**Verification/size.** **M**, after M04 and command policy. `tests/agent-control.test.ts` runs fixture CLI calls for missing/wrong/revoked/expired grants, other projects/generations, flood/fanout, child-token stripping, duplicate notes/opens, lost ACK, stale revisions, restart and unauthorized verbs. `scripts/verify-agent-control.mjs` proves one agent-created session/note reaches the existing canvas and parent view detaches without stopping either process. No provider calls needed. Owner default: explicit per-session grant, status/notes before session creation; automated fanout stays off unless enabled. Grant limits/expiry block only the automation milestone.

## 5. Opt-in AI commit messages and terminal names

**Journey.** “Suggest message” in ReviewPanel previews the exact staged diff to be shared, provider/profile/model and usage notice. One explicit action generates an editable draft; Commit remains the existing separate user action. “Suggest name” uses user-selected task/prompt context, not an automatic terminal scrape; Accept saves a plain text session label. No background/on-launch generation, silent replacement of user text or automatic commit/stage/push.

**Implementation.** Add `src/core/assist.ts`, a host-local helper runner and `src/desktop/assist.ts`; extend `ReviewPanel.tsx`, `SessionView.tsx`, `sessions.ts`, contracts and D-only `workspace:assist`. M01 stores disabled-by-default settings and accepted session title/revision, not raw prompts or provider results by default. Generate from an immutable bounded staged-diff snapshot/hash using existing safe Git diff flags; exclude binary bodies, cap bytes, visibly report omitted paths and let the owner exclude sensitive material. Nothing reads unstaged/untracked files or full terminal output without separate selection. Return draft plus source hash; if staging changed, mark stale and require review/regeneration. `session.rename` is D/R metadata only and cannot trigger a model.

**Enforced read-only execution.** A prompt saying “do not edit” and a print flag are insufficient. Run the installed CLI from a private empty scratch cwd with only the selected frozen input on stdin; sanitized environment must strip agent-controller tokens, SSH agent handles and unrelated provider keys. Suppress project instructions, extensions, tools, MCP, hooks and inherited customizations with verified flags/effective configuration, plus applicable OS/filesystem sandbox restrictions. No repo write mount, command execution tools or unrestricted context discovery. Bound runtime/output, concurrency and supported budget controls, and kill the helper process group on cancel; timeouts never trigger an automatic paid retry.
